# リリース計画 — マイクラ Mod プロジェクト（ai-programing-exercise）

## 概要

本ドキュメントは、TDD で進める Minecraft Mod 開発プロジェクトのリリース計画を定義する。インセプションデッキ（@docs/strategy/inception_deck.md）とユーザーストーリー一覧（@docs/requirements/user_stories.md）を入力としている。

### プロジェクト情報

| 項目 | 内容 |
|------|------|
| **プロジェクト名** | ai-programing-exercise mod |
| **目的** | TDD・XP プラクティスを Minecraft Mod 開発を題材に体得する。受入テストを実環境（GameTest）で自動実行する経験を積む |
| **対象ユーザー** | Modder（自分）／プレイヤー／CI |
| **開発チーム** | 1 名（個人 + Claude Code エージェント） |
| **Mod ターゲット** | NeoForge 1.21.11（Java） |

---

## 満足条件

### スコープ

「最小起動 → GameTest 確立とカスタムブロック → アイテム / クラフト → ワールドジェン」と段階的にワールド要素を増やす 4 リリース構成。Phase 1 では JUnit 中心の CI を確立し、Phase 2 で GameTest ハーネスとカスタムブロックを一体で立ち上げる。各リリース完了時点で `gradle test`（Phase 1 以降）と `runGameTestServer`（Phase 2 以降）が green であることを必須とする。

| フェーズ | 内容 | ストーリー数 |
|---------|------|--------------|
| Phase 1（v0.1.0 MVP） | 起動 / JUnit / CI | 3 |
| Phase 2（v0.2.0） | GameTest ハーネス + カスタムブロック | 4 |
| Phase 3（v0.3.0） | アイテム / クラフト | 2 |
| Phase 4（v0.4.0） | ワールドジェン（構造物 / バイオーム） | 2 |
| **合計** | | **11 ストーリー** |

### スケジュール

- **開発期間**: 8 週間（個人プロジェクトのため週次稼働は変動可、目安）
- **イテレーション**: 2 週間 × 4 イテレーション
- **リリース**: 各イテレーション末にマイナーバージョンを切る段階的リリース

### リソース

- **開発者**: 1 名（自分）
- **AI エージェント**: Claude Code（ペアプロ的協働）
- **想定稼働時間**: 5〜10 時間 / 週（学習目的のため可変）

4 軸評価で優先順位を決定する。

## ベロシティ見積もり

### 初期ベロシティ推定

| 項目 | 値 |
|------|-----|
| **イテレーション期間** | 2 週間 |
| **チーム規模** | 1 名（+ AI エージェント） |
| **想定ベロシティ** | 8〜12 SP / イテレーション |
| **バッファ係数** | 0.8（20%バッファ） |
| **実効ベロシティ** | 約 6〜10 SP / イテレーション |

### ベロシティ検証計画

- IT-1〜3 の実績を計測し、IT-4 開始前にベロシティを再校正する。
- 個人プロジェクトのため週次稼働の変動を吸収するスケジュールバッファを確保する（後述）。
- ストーリーポイントは「最小実装＋ GameTest 作成＋ JUnit 化＋ CI 通過」までを含む。

### ベロシティ実績（IT-1 / IT-2 完了時点）

| イテレーション | 計画 SP | 実績 SP | 注釈 |
|---------------|---------|---------|------|
| IT-1 | 5 | 5 | 元計画 8 SP → API 刷新発見で US-002 を IT-2 へ移送、5 SP に縮小 |
| IT-2 | 11 | 11 | GameTest ハーネス確立 + カスタムブロック / 6 件の問題を解決しつつ完走 |
| **平均** | **8** | **8** | サンプルが 2 IT のためまだ仮値。3 IT 後に再校正 |

実測ベロシティが想定範囲（8〜12 SP/IT）の下限近くに収束。IT-4 (13 SP) は最大値に近く、リスクとしては予備イテレーション IT-5 を発動する可能性が中程度。

### リリース内容

#### Release v0.1.0（Phase 1 完了）: MVP — 起動と JUnit / CI 確立

**目標**: ユニットテストと CI で保護された土台を確立する。

**含まれる機能**:

- Mod がクライアントで起動する
- JUnit 5 でロジック層を単体テストできる
- CI（GitHub Actions）で push / PR ごとにビルド + JUnit テストを自動実行

**リリース条件**:

- [ ] 全 JUnit テストが green
- [ ] CI が green（`gradle build test`）
- [ ] `runClient` でログに Mod ID が表示される

#### Release v0.2.0（Phase 2 完了）: GameTest ハーネス + カスタムブロック

**目標**: 受入テストハーネスを確立し、ワールドにカスタムブロックを 1 つ追加して配置・破壊・取得が GameTest で保護される。

**含まれる機能**: US-002, US-101〜103

**リリース条件**:

- [ ] `runGameTestServer` が green（最小サンプル + ブロック関連テスト）
- [ ] CI に `runGameTestServer` ステップが追加され green
- [ ] CI が green

#### Release v0.3.0（Phase 3 完了）: アイテム / クラフト

**目標**: カスタムアイテムとクラフトレシピを導入する。

**含まれる機能**: US-201〜202

**リリース条件**:

- [ ] 全 GameTest が green（インベントリ / クラフト）
- [ ] CI が green

#### Release v0.4.0（Phase 4 完了）: ワールドジェン

**目標**: カスタム構造物 / バイオームをワールドに追加する。

**含まれる機能**: US-301〜302

**リリース条件**:

- [ ] 全 GameTest が green（構造物配置 / バイオーム判定）
- [ ] CI が green

### スケジュールバッファ

1. フィーチャバッファを先に消費（低優先ストーリー US-103, US-302 から後回し）
2. それでも収まらない場合は IT-5 を発動
3. ベロシティが想定下振れの場合は Phase 4 のスコープを優先的に削る

## イテレーション計画概要

### イテレーション 1（Week 1-2）

**ゴール**: Mod が起動し、JUnit ユニットテスト・GitHub Actions CI が緑になっている状態を作る。

**主なタスク**:

- [ ] Mod ID を `aipe`（仮）として確定し、起動ログを確認
- [ ] JUnit 5 依存追加 + サンプルテスト
- [ ] GitHub Actions ワークフロー作成（`./gradlew build test`）

**目標 SP**: 5

詳細は [iteration_plan-1.md](./iteration_plan-1.md) を参照。

### イテレーション 2（Week 3-4）

**ゴール**: GameTest 受入ハーネスを確立し、カスタムブロックを 1 つ実装してワールドへ設置・破壊・取得が GameTest で保護されている。

**主なタスク**:

- [ ] `.gitattributes` 追加（IT-1 ふりかえり Try）
- [ ] `RegisterGameTestsEvent` 経由で `FunctionGameTestInstance` 登録（US-002）
- [ ] NeoForge データジェネレーターで NBT 構造 + loot table を生成
- [ ] `aipe:example_block` の設置・破壊・回収 GameTest（US-101 / US-102）
- [ ] `EXAMPLE_TAB` に `example_block` を追加（US-103）
- [ ] `aipe-ci.yml` に `runGameTestServer` ステップ追加

**目標 SP**: 11

詳細は [iteration_plan-2.md](./iteration_plan-2.md) を参照。

詳細は IT-1 完了後に [iteration_plan-2.md](./iteration_plan-2.md) として作成する。

### イテレーション 3（Week 5-6）

**ゴール**: カスタムアイテム + クラフトレシピが動作する。

**目標 SP**: 8

### イテレーション 4（Week 7-8）

**ゴール**: カスタム構造物 / バイオームがワールドに生成される。

**目標 SP**: 13

## リスク管理

### 技術リスク

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| GameTest が CI（ヘッドレス）で動作しない | 高 | 中 | IT-1 の最初に最小サンプルで CI 動作確認を実施 |
| NeoForge / Minecraft の API 仕様が想定と異なる | 中 | 中 | 公式ドキュメント / community example を参照、最小実装で動作確認後にスコープ拡大 |
| GameTest 用構造ブロック（NBT）作成のハードルが高い | 中 | 中 | IT-1 では「空構造 1×1×1」で開始、必要に応じて拡張 |
| 1.21.11 のマイナーバージョン更新で API が壊れる | 中 | 低 | バージョン固定（gradle.properties）、更新は明示判断 |

### スケジュールリスク

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| 個人プロジェクトゆえ週次稼働が下振れる | 中 | 高 | フィーチャバッファ 30% + 予備 IT-5 |
| 学習目的で寄り道が発生し計画から逸脱する | 中 | 中 | 寄り道は「学習ジャーナル」に分離し、リリーススコープは堅持 |
